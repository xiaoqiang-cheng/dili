# Dili 产品需求文档

> 把 Claude Code、Codex、DeepSeek Harness 的具体会话变成联系人卡片：在外面看状态，点进去继续原生交互，需要协作时再组成群组。

- 版本：v0.4.0-dev.0（开发中）
- 日期：2026-10-20
- 产品形态：本地优先的 Web 应用
- 当前目标：完成会话联系人、原生交互和 Fork，并实现基础群组闭环
- 价值判断：以日常使用是否顺手为准，不以商业化为目标
- 后续优化计划：见 [TODO.md](TODO.md)，已选方向待用户指定实施顺序

## 品牌

产品名称为 **Dili**，中文名为 **嘀哩工作台**。

> **让每一次 AI 对话，都能继续成为工作。**

Dili 的视觉标识采用 **35 四向工作（Shared Centre）**：四块向中心收拢的几何形，表达多个独立会话围绕同一任务共同推进。页面内的标志使用主题强调色、文字色和次要文字色，随浅色、暖色和深色主题切换。`public/logo.svg` 为横版组合；`public/icon.svg`、`public/favicon.svg` 与 `public/icon-maskable.svg` 用于应用图标，独立 SVG 根据系统深浅色偏好适配配色。

Logo 设计方向保存于 [设计选型文档](docs/logo-concepts/README.md)，已选用第三轮的 **35 四向工作**，并调整为与应用主题一致的配色。各轮原始草案保留作为设计记录。

仓库目录、`SESSIONDECK_*` 环境变量、`X-SessionDeck-*` 请求头和浏览器存储键保留为兼容标识。它们属于内部接口，不影响产品名称，也避免升级后丢失已有会话、笔记和远程配置。

## 安装与产品化

首个正式发行目标为 Linux x86_64 / WSL2、Node.js 24+。支持预构建 npm 包和 `dili` 命令，程序安装目录与用户数据分离；包名暂定 `dili-workbench`，**尚未发布到 npm**。本地 `npm pack` 后可以安装 tarball。

设置页提供原生 Agent 安装/登录终端、Claude/Codex API 配置和 Linux systemd 用户服务自动启动。DeepSeek Harness API 配置复用其原生 Web 设置。配置供其他终端的原生命令共享，保存会备份已有文件。安装不会自动使用 sudo；自动启动开关不停止或重启现有会话。

语音输入作为可选 FunASR 插件提供：在本机设置中一键安装并启用，默认不下载模型。三平台图形输入支持实时语音预览，录音结束后追加草稿，由用户确认发送；手机录音通过现有可信中继交由主机识别。采用独立 Python / CPU 工作进程和压缩音频二进制分片，不落盘音频，中继代码无需更新。已在隔离目录验证真实安装和模型加载，麦克风识别效果与设备体验仍需验收，详见安装指南的语音输入章节。

详见 [安装指南](docs/installation.md) 和 [正式版发布清单](docs/releasing.md)。自动化命令：`npm run verify` 与 `npm run test:package`。Windows 原生与 macOS 尚未完成发行验收；WSL 的服务在发行版启动后运行，不等同于 Windows 开机启动。

新建联系人和群组新成员可选择「原生默认」或「Auto · 自动审核」。旧联系人沿用原生默认；同平台 Fork 继承来源选择。Claude 使用原生 `--permission-mode auto`，Codex 使用 `--approve-for-me`（图形会话通过原生审批审核器与 workspace-write 沙箱），Harness 使用原生 Auto 权限预设。Auto 会减少人工审批，仍受原生审核规则和可用性限制，不等于跳过所有权限保护。设置只保存到该联系人，不修改原生全局配置；Harness 需安装并配置原生 Auto 审核能力。

## 1. 产品定义与优先级

Dili 管理的是**一个个具体会话**。同一个后端可以有多个联系人，例如三个 Codex 会话分别负责实现、审查和实验。联系人不是模型，也不是一个固定的 Agent 人格。

核心体验：

1. 打开网页，看到自己各个后端的会话联系人卡片。
2. 不进入会话，就能辨认它正在运行、等待自己处理、出现异常，或状态尚不确定。
3. 点击卡片，进入该会话，继续输入、纠正方向或处理原生审批。
4. 为卡片改名，或把已有上下文 Fork 成另一个独立联系人。
5. 后续在群组中组织共同任务：新建成员，或将已有会话 Fork 入群；随时单独进入成员会话纠正。

优先顺序：**会话卡片与进入会话 → Fork → 基础群组**。本轮交付覆盖三个阶段；群组不能挤占卡片体验，也不能只留下空壳入口。

## 1.1 现成工具与是否值得做

已有工具覆盖了多会话管理、终端复用和 Agent 协作等相邻需求。选型要同时检查三个条件：**跨 Claude Code、Codex、DeepSeek Harness 的具体会话联系人卡片、可点击回到原生会话、由用户主导的跨后端群组**。支持多个模型或多个终端，并不自动满足这三个条件。

| 工具形态 | 已经解决的事情 | 与本项目需求的差距 |
|---|---|---|
| 各后端自己的 CLI / Web / app-server | 原生登录、审批、历史、Fork 和会话交互 | 各自独立，不能提供统一联系人、跨后端状态和群组入口 |
| tmux、Zellij、终端标签页 | 同时挂起多个终端，切换很快 | 只管理终端窗口，不知道原生会话身份、提醒或群组消息关系 |
| VS Code / IDE 插件 | 在编辑器中使用某一个 Agent，复用部分原生能力 | 通常绑定单一后端或工作区，不能可靠承载三种后端的精确会话与跨会话 Fork 关系；插件也不能直接当作 Web UI 嵌入 |
| Claude Squad、Conductor 等多 Agent 工作区 | 并行管理编码任务，有的结合 Git worktree | 还需逐项核实 DeepSeek Harness 原生接入、精确会话状态、上下文 Fork 和用户主导的群组路由 |
| OpenHands、ChatDev 等 Agent 工作台 | 提供统一聊天或自动协作界面 | 往往重新实现 Agent 交互，不能直接复用用户已有 CLI 的登录、审批和原生上下文 |

Dili 的价值是减少个人开发者在多个原生会话之间切换的认知和操作成本。只要卡片状态可信、点击不串会话、Fork 不丢上下文、群组投递可追踪，它就有明确的日常价值。首版坚持本地优先、用户确认投递和原生能力复用，控制开发量并验证这个核心假设；如果现成工具已经能完整满足这些工作流，也优先采用现成工具。

## 2. 复用原则

- 优先复用后端自己的 CLI、认证、权限确认、恢复和 Fork 能力。
- Codex 通过原生 app-server 提供可交互的「图形对话」，也可切换到同一会话的原生终端；认证、模型、工具执行和权限决定仍由 Codex 处理。Claude Code 图形模式复用官方 stream-json，提供流式回复、工具、审批和问题回答；图形与终端通过同一持久会话交接。dsh-tui 在统一 Markdown 界面中直接发送，复用原生终端输入及日志；没有 dsh-tui 时，Harness 继续复用自己的 Web 界面。
- 保留后端原生交互习惯。Dili 提供联系人、状态、入口和群组组织。
- 能通过受支持的原生接口完成的工作，不读取内部数据库后自行模拟。
- 不假定 VS Code 插件能够直接嵌入网页。只有接口、运行环境和许可证合适时才复用其实现。
- 后端不具备或尚未验证的能力，明确标注不可用及原因；不能用看起来成功的假操作代替。

## 3. 用户与工作流

面向同时使用 Claude Code、Codex、DeepSeek Harness（下称 dsh）的个人开发者。这里的“跨平台”首先指跨这三种 Agent 后端；首版无需同时交付桌面应用、移动应用和多操作系统安装包。

典型工作流：创建“登录实现”Codex 联系人 → 图形对话中布置任务 → 返回卡片查看状态 → 提醒后点击原会话处理 → Fork 出“登录方案实验” → 建立“登录功能”群组 → 在群内新建 Claude 设计成员、dsh 验证成员，或 Fork 已有联系人入群 → 分别派发任务、纠正成员、共享结果。

## 4. 会话联系人

### 4.1 卡片内容

| 字段 | 展示要求 |
|---|---|
| 名称 | 用户可随时修改，持久化保存 |
| 后端 | Claude Code / Codex / DeepSeek Harness |
| 状态 | 清晰徽章；未知或推断状态可辨认 |
| 最近活动 | 时间及适合显示的简短说明 |
| 提醒 | 等待输入、审批、异常等需要关注的信息 |
| 工作目录 | 帮助区分项目，可缩略显示；旁边的复制按钮一键复制完整路径，不打开会话 |
| 最近输入 | 显示原生历史中最近一条真实用户输入的简短摘录，最多 240 字符、列表中单行省略；无可读历史时显示简短状态说明 |
| 关系 | 可识别群组归属及 Fork 来源 |

会话卡片按置顶 → 红点提醒 → 正在执行任务 → 无红点等待输入 → 其余分层排列。同层默认按上次用户输入时间倒序，也可选择创建时间倒序或名称自然排序；缺少输入时间的联系人排在该层有输入记录的联系人之后，时间相同时按创建时间、名称排列。支持名称、目录和最近输入摘录搜索、后端及状态筛选、归档与查看归档。筛选按页面保留；复杂标签、全文检索、成本统计和多套布局不属于首版必要条件。

最近输入与状态分别展示，不把工具结果、终端控制字符或系统指令当成用户任务。摘录保存在本地联系人元数据中，不调用模型生成摘要；刷新摘录不会增加未读提醒或改变最近活动时间。运行会话约每 5 秒、非运行会话约每分钟读取一次，分批限制并发；历史尚未落盘、很多联系人或文件索引尚未刷新时会有延迟。待初始化的 Fork 不冒用来源会话的记录。

### 4.2 卡片操作

- **新建**：选择后端、名称、工作目录，创建可交互会话。
- **进入**：打开同一个会话；重开详情不得无声创建新上下文。
- **改名**：只需改变本工具中的显示名称，不要求后端也支持重命名。
- **Fork**：调用后端原生分叉，产生新联系人并记录来源。
- **归档**：收起联系人并保留信息；运行中的进程如何处理必须明确。
- **恢复 / 停止**：按后端和进程实际能力展示；停止不是删除历史。

新建或恢复会话前检查原生程序是否存在，并显示可操作的失败原因。登录与模型使用额度沿用用户自己的后端配置。dsh 的 Web 服务按需启动，会话入口仍然指向具体的原生会话。

在群组中新建成员时，默认沿用该群组最近活跃成员的工作目录；也可显式选择最近使用的目录，或填写其他已有目录。切换后端不会覆盖已填写的路径。本工具不会因为选了一个目录就新建工作区或 Git worktree。

新建联系人、群内新成员及 Claude/Codex Fork 的目录字段均支持「浏览」：弹出网页内目录资源管理器，可逐层进入、返回上一级、回到主目录、显示隐藏目录、筛选文件夹并选择当前目录。也可粘贴绝对路径、带引号的路径、`~/` 路径或 `file://` 目录链接，中文与空格按实际路径处理。只列出目录，不上传项目文件。

目录属于**运行 Dili / Agent 的电脑**；从另一台电脑访问时同样如此。这里使用网页弹窗而非操作系统原生文件选择器，因为浏览器通常不会提供可交给本机 CLI 的绝对路径。不存在、无权限或粘贴了网页 URL 时显示错误并保留表单。

### 4.3 会话身份与接入范围

Dili 的 `id` 用于卡片和群组关系；`nativeSessionId` 指向后端真正的会话，两者不得混淆。某些后端只有启动并产生事件后才能获得原生 ID；此时显示“尚未识别”，不能拿卡片 ID 冒充。

卡片创建并启动后即可精确进入其托管进程。支持原生 app-server 的 Codex 版本在创建时即取得真实线程 ID，Fork 也直接返回独立子会话 ID；原生终端连接到同一线程。旧版本使用兼容终端路径，通过完成通知确认原生 ID，确认前不能 Fork。工具不凭“相同目录、相近时间”猜测会话身份。

首版优先可靠管理 **Dili 自己启动或通过原生 ID 恢复的会话**。支持显式发现并导入本机历史会话；发现磁盘中的历史会话，不等于能接管另一个终端中正在运行的进程。

Codex 会话若被桌面应用、VS Code 插件或另一个 app-server 占用，原生恢复会返回 `already has an active writer`。联系人和历史仍保留，私聊页提供「重试恢复」和「Fork 后继续」：前者在原客户端释放会话后恢复同一 ID，后者调用原生 Fork 创建独立 ID 并继承上下文，保留原客户端。Dili 不抢占原生写入锁，也不停止外部进程。

导入列表会标记已删除、已移动或无法访问的工作目录。可用「更换目录」选择服务器上的现有目录或粘贴目录链接后添加；目录在发现后失效时，添加失败也会提供同样的修复入口。Codex 恢复会通过原生 `thread/resume` 使用所选目录，保留原会话 ID；项目文件需要自行迁移。历史发现出错时提供重试，避免误报为没有历史。

外部历史接入必须使用后端原生恢复能力。任意现有终端进程的接管、所有历史的自动导入、跨设备同步均可后置。已有联系人的只读记录使用有界索引定位文件，只读取该联系人精确原生 ID 对应的内容。

#### 用户输入目录与历史分页

Codex／Claude 图形对话工具栏的「对话目录」列出当前已加载的用户输入，按对话顺序显示序号和原文摘要，支持按完整已加载输入的关键词筛选。宽面板在消息右侧展开独立滚动的目录；手机或宽度不超过 720px 的会话面板使用浏览器原生模态抽屉，避免挤压消息。点击条目定位到对应输入并短暂高亮，可继续查看其后的回复；相同输入通过消息 ID 区分。手机点击后自动关闭目录，Esc 只关闭目录，保留当前会话。

历史范围、记录省略等说明使用会话内右上角浮动提示，不占消息区布局；可点 × 关闭，默认 6 秒后自动收起，鼠标悬停或键盘聚焦时暂停计时。同一标签页内关闭或自动收起后，刷新、流式更新和重新进入会话不重复显示同一提示；不同原生会话分别记录。审批、发送结果待确认和需要重试的错误仍保留操作入口。

查阅历史时新的流式回复不会强制滚回底部，可点击「回到最新消息」恢复跟随。目录只负责查看历史位置，不回滚、重发或 Fork 会话。原生记录仍然是唯一历史来源；目录不额外保存对话，也不支持在原生终端或 Harness 内嵌页面定位。目录只列出当前加载范围内的输入，序号不是全会话绝对编号；加载更早消息后，目录自动补入对应用户输入。覆盖全部历史而无需逐页加载消息的独立输入索引仍待实现。

Codex 图形会话首屏通过原生 `thread/turns/list` 读取最近 20 轮，不请求 `thread/read(includeTurns: true)` 的全量历史。消息区顶部的「加载更早消息」或目录中的「加载更早输入」通过原生游标继续读取旧页，保留当前阅读位置；失败后保留已显示消息并允许重试。原生分页响应超过帧上限时缩小为 5 轮、再到 1 轮；单次分页 RPC 最多等待 5 秒，仍不可读取或原生版本不支持分页时回退到有界的本地历史，不再尝试全量读取。同一会话的并发首屏请求合并，成功后 2 秒内复用原生实时快照；失败短期冷却，避免反复请求同一不可用历史。事件流先发送已有快照，再补齐最新记录，历史连接独立于持有输入和审批的实时连接。

Claude 图形对话直接分页读取原生 JSONL，首屏及每页最多 40 条消息，单次扫描窗口最多 2 MiB，只解析完整记录；停止中的会话也能只读查看，不为读取历史启动 CLI。超长文本截断，巨型工具或图片记录可能省略，空页仍可继续向前加载。用户消息和最终回复复用原生保存 UUID，实时消息被最终消息替换时保持去重；重连到新的 Dili 服务实例后丢弃旧游标与晚到结果，保留草稿。刚 Fork 的 Claude 尚未写出独立历史时，先显示源会话最近一页，首次任务落盘后启用子会话历史分页；此前不能用源游标翻阅子会话旧页。

目录计数代表已加载输入，不是全会话总数。原生输入连接未就绪时，可点击「重新连接原生会话」恢复该会话的观察连接；重连保留历史与草稿，不自动发送或重启 Agent。仅恢复元数据的原生响应不会清空现有消息。后端更新需正常重启 Dili 服务后生效；只刷新网页无法更新仍在运行的服务端代码。

实时快照仍最多保留 200 个项目、512,000 字符；额外已加载旧消息最多保留 1,000 个项目、2,000,000 字符，达到上限会提示，重新进入会话可释放这些前端记录。超长单轮或工具输出可能省略；完整原生上下文不会因此删减。分页查看不改变当前轮次、审批或其他浏览者的历史范围。

### 4.4 随手记

顶部「随手记」打开右侧全局笔记，与资源管理器、会话和底部终端独立收起。桌面可拖动调整宽度；窄屏或笔记本同时打开文件预览时浮在右侧，给会话保留空间；手机全屏打开。默认使用 Vditor 的即时渲染模式，像 Typora 一样直接在呈现的 Markdown 中编辑：标题、加粗、列表、待办和表格边写边呈现，光标进入后可编辑标记。可切换「实时／源码／预览」，浏览器记住显示方式；支持勾选待办和导出 `.md`，一张笔记最多 30,000 字符。编辑器及解析器资源随应用本地提供，不依赖外部 CDN；图片保留 Markdown 链接但不请求图片，原始 HTML 不执行，图表和公式保留源码。仅打开或切换模式不会改写原文；实际实时编辑后组件会规范化 Markdown 空白与列表标记。

输入后自动保存到本地 SQLite 数据库，关闭面板、刷新和服务重启不删除内容；远程所有者访问同一份笔记，分享会话无权读取。未保存草稿保存在当前浏览器，断网、保存失败或刷新后可恢复。多端版本冲突时保留草稿，提供最新内容供核对，由用户选择保存自己的内容或使用最新内容。清空需要确认，并可在本次页面中撤销；切换会话不改变笔记。

## 5. 状态与提醒

### 5.1 状态语义

| 状态 | 含义 |
|---|---|
| 运行中 | 有可信依据表明后端正在处理工作 |
| 等待输入 | 后端正在等待用户补充内容 |
| 等待审批 | 后端在等待用户批准操作 |
| 空闲 | 当前可继续交互；不代表用户任务已验收 |
| 已停止 | 托管进程结束，保留卡片与历史 |
| 异常 | 启动失败、进程错误或明确后端错误 |
| 未知 / 连接中断 | 缺乏可靠依据或失去连接 |

归档是联系人生命周期属性，不混入执行状态。后端结束一轮输出，不自动代表任务完成；任务完成和结果验收另行记录。

### 5.2 可信度要求

状态同时记录来源、解释和更新时间：

- **原生**：来自受支持的结构化事件或可验证的进程生命周期。
- **推断**：来自终端提示或输出特征；界面标明推断，允许进入核对。
- **未知**：没有足够依据；不杜撰进度和完成状态。

仅凭一段时间没有输出，不能认定 Agent 已完成、阻塞或等待审批。用户普通文本中出现“approve”等词语也不应直接触发确定性审批提醒。

卡片通过实时事件更新，关键状态变化产生站内提醒。提示音默认开启，可用顶部扬声器按钮静音；浏览器需要页面首次点击或键盘操作后才能播放。系统通知单独授权，未授权系统通知时卡片提醒与提示音仍能使用。刷新网页后保留会话，不把历史消息重复当作新提醒。

## 6. 私聊路径：Web 中使用原生会话

联系人采用微信／飞书式紧凑列表：头像、名称、最近输入、时间、状态和未读提醒。桌面左侧列表与右侧会话并排，选中行高亮，点击其他联系人直接切换同一原生会话；列表宽度可拖动或用分隔条方向键调整并保存。顶部不再使用浏览器式会话标签。手机默认显示联系人列表，进入后只显示单会话，点返回、× 或浏览器返回回到列表。关闭面板与切换联系人不会停止 Agent。新建与导入入口并列。群组页桌面左侧列成员、右侧显示群组动态或成员私聊。顶部导航、独立 Shell 多终端／分屏、文件树、并排 Markdown 预览及 Git diff 保留原有操作；打开联系人不会自动展开资源管理器，需要查看文件时再手动打开。

Codex 与支持 stream-json 的 Claude 在无已保存偏好时默认使用可交互的「图形对话」：用户在网页输入任务，回复实时流入，并渲染 Markdown、列表、表格和带语法高亮的代码块；代码可一键复制。命令、文件修改和工具输出以可展开卡片展示，执行计划单独展示。图形对话目前仍以文本任务为主；图片支持选择、剪贴板粘贴和图形输入区拖入，发送前显示可移除缩略图。支持 PNG、JPEG、GIF、WebP，单张不超过 10 MiB，图形草稿每条最多 8 张。Codex 图形对话通过原生 app-server 的 localImage 输入发送，可单独发送图片；Claude 图形模式通过原生 stream-json 提交文字和图片；dsh-tui 图形模式复用原生图片路径粘贴协议并提交，不要求切换终端再按回车。直接使用原生终端的图片粘贴入口时，仍由用户确认原生附件并按回车。Claude 和 dsh-tui 原生终端的图片路径分别粘贴，不与正文拼成一个路径；Harness 是否接受图片仍取决于已安装 TUI、原生附件服务和所选模型能力。Claude 结构化图形模式支持网页内审批；dsh-tui 的审批仍在原生界面处理。未安装 dsh-tui 的 Harness 继续使用原生 Web 界面。IDE 文件编辑器和完整 Diff 编辑器不在本轮范围。

终端工具栏提供复制选区和粘贴入口，Ctrl/⌘+C 在有选区时复制，Ctrl/⌘+V 保留浏览器原生粘贴；Linux 也可用 Shift+Insert。剪贴板读取受浏览器权限及安全上下文限制，无法读取时提示使用快捷键或图片选择。长粘贴分帧发送，图片上传期间的并发按键按顺序暂存；连接或视图切换时未发送的暂存内容保存在当前标签页输入栏，供用户确认后发送。

会话顶部使用单行标题栏，名称、视图切换、目录、刷新、终端操作、启停和关闭合并在同一行，不再额外占用副工具栏。按会话面板实际宽度收起次要操作，窄屏从「会话工具」展开，支持 Escape 关闭并恢复焦点；「更多」中可查看完整状态、后端与工作目录，以及改名、群组、Fork 来源等操作。文件预览打开后也遵循同一规则。三平台共享消息排版：用户消息靠右、助手 Markdown 通栏显示，统一阅读宽度和间距。联系人列表采用柔和底色与选中标记，会话内容直接填满右侧面板。

交互通过 [Codex app-server](https://developers.openai.com/codex/app-server/) 的原生线程、事件、审批和中断协议实现，这是 Codex IDE 扩展使用的服务能力。复用用户安装的 Codex 和现有配置，不另建模型调用链，也不直接嵌入 VS Code 插件。

Codex／Claude 结构化图形模式提供统一「会话设置」。输入 `/` 显示带图标与说明的命令菜单，支持 ↑／↓ 选择、Enter 打开、Esc 收起，可筛选 `/settings`、`/model` 或 `/permissions`。输入框下方另有独立「模型」「权限」按钮，展开后读取当前原生值、选择并明确应用；快捷按钮与完整设置面板共用状态，保留草稿。模型选项直接来自已安装 Agent 的原生列表，权限修改须收到原生确认；任务／审批进行中不能切换，仅所有者可修改，分享访问只能查看。Codex 保留现有沙箱，仅切换审批方式；Claude 提供默认审批、自动接受编辑与计划模式。设置作用于当前原生线程或图形执行器，不写用户全局配置；重开或切回终端后重新以原生配置为准。未报告的值和不支持的能力明确提示，不伪装设置成功。

原生命令／文件／权限审批显示操作详情和原生可选决定；用户明确选择后才答复。原生提问显示选项及协议允许的补充输入。不支持的请求明确提示转到原生终端处理。断线或已由其他界面处理的请求不能继续使用过期审批。

Codex 输入框的「停止生成」只中断当前一轮，并暂停已排队消息，随后仍可继续聊天；详情顶部的「停止会话」结束该联系人的托管连接和终端。Codex 图形模式创建／恢复不启动 TUI，切换到「原生终端」时连接同一个原生线程；切回图形模式不会重启会话。普通草稿不会因切换卡片、刷新或读取历史自动提交；用户明确加入队列的消息按下文规则恢复。

草稿和待确认的发送标识保存在当前标签页的浏览器存储中，刷新、关闭详情再打开时恢复。服务端先持久化发送标识，再交给原生 Agent；同一标识不重复执行。响应丢失时显示「发送结果待确认」，先查询结果，仍未知则由用户核对原生历史后确认，禁止自动重发。服务重启也保留待确认记录；数据库仅保存发送标识、文本摘要哈希及结果，不额外保存私聊正文。

Claude Code 的「图形对话」使用已安装 CLI 的官方 stream-json，复用认证、工具、持久配置和原生历史，支持实时 Markdown、图片、工具结果、审批、问题和停止生成。与 Codex 共用平台无关的 `AgentChatPane` 和聊天 API。Claude 的图形执行器与 TUI 是不同进程，不能同时写入一个联系人；切换要求当前任务和审批结束、用户明确确认，退出旧执行者后恢复同一持久会话 ID，不承诺继承仅存在于原进程内存中的设置。已有 PTY 联系人不会因刷新被自动替换。实现说明与验收见 [Claude 图形会话](docs/claude-streaming.md)及[架构改造方案](docs/graphical-workbench-architecture.md)。

Claude 旧 PTY 兼容视图与 dsh-tui 仍保留原生终端直接发送路径，审批在原生界面处理。Claude 明确切换后使用结构化图形路径。点击发送或按 Enter 提交，Shift + Enter 换行，中文候选确认不误发；发送结果不确定时保留草稿、提供核对入口并阻止自动重发。Claude 旧草稿可恢复，跨执行者的排队消息暂停等待确认。未安装 dsh-tui 时沿用 Harness 原生 Web 会话。

原生会话终端与底部 Shell 的默认背景、文字、光标、选区及 ANSI 基础色跟随页面实际配色，工具栏和手机输入栏使用同一套页面颜色。页面配色变化时直接更新已打开的终端，保留连接、内容和输入焦点。原生工具显式指定的真彩色或内部主题仍由该工具控制。

顶部调色盘按钮或「更多 → 外观主题」提供简洁浅色、柔和暖色、沉静深色、午夜靛蓝、终端黑绿、高对比度及跟随系统。默认跟随系统，手动选择后不受系统明暗变化影响；偏好在当前浏览器中持久保存并同步其他标签页。主题统一覆盖联系人、随手记、会话、Markdown 代码、文件预览、Git diff、弹窗与提示，不改变布局或重启原生进程。手机会话中可从「会话信息」打开随手记或外观主题。

设置页和外观弹窗提供 **100%–200% 界面缩放**滑块，实时调整并在当前浏览器保存、同步标签页，可恢复 100%。终端字号、面板拖动和目录定位同步缩放，保留连接与草稿。

三个平台的图形对话／对话记录都提供「对话目录」：按用户输入筛选、跳转并高亮原消息，桌面并排、窄面板抽屉显示。目录只覆盖已读取的历史，Codex 可继续加载更早消息；Harness 仅有原生 Web 界面时也可切换到记录页查看目录，不模拟原生终端滚屏。

图形输入区复用工作区 splitter，上沿拖动高度、左右边沿拖动宽度，支持方向键并保存尺寸。会话标题栏提供全屏按钮，Ctrl / ⌘ + Shift + Enter 切换，Esc 先关闭目录再退出全屏；全屏不重新创建会话连接，也不清空草稿。底部终端省略独占一行的工作目录，目录保留在标签提示中。联系人头像使用 Claude 星芒、OpenAI 结标和 DeepSeek 鲸鱼，[标识来源](docs/backend-logos.md)随仓库保存。

Codex 生成中允许继续发送，复用原生 `turn/steer`，追加到当前任务；任务 ID 变化、等待审批或发送结果不确定时保留草稿并要求核对，不自动停止、不另开一轮重试。不支持该原生方法的旧 Codex 会明确报错。已移除单独的模型输入框，沿用原生会话配置。Claude 结构化模式生成中发送会加入可编辑、可取消的队列，在本轮结束后继续；dsh-tui 的补充输入由原生工具决定何时消费，也可显式加入队列。

三平台生成期间还可选择「加入队列」，输入区上方显示待发送消息，支持编辑、取消和立即发送，最多 10 条，支持图片。队列在原生确认本轮结束后逐条提交，不承诺精确在「下一次工具调用后」发送；终端静默或估测状态不能触发自动投递。离开图形会话时暂停自动提交，重新进入且原生空闲时恢复；草稿和队列保存在当前标签页的 sessionStorage，支持刷新恢复，不承诺关闭整个标签页后保留。原生身份改变、明确拒绝或发送结果不确定时暂停该条，需核对后手动处理。队列发送不覆盖正在编辑的新草稿，停止生成也会先暂停队列。

记录和图形对话都绑定精确原生 ID，支持滚动回看和选中文本共享。Codex 图形流保留最近 200 个消息／工具条目，总文本与单条内容都有上限，截断时提示完整历史仍在原生会话中。未启动会话先只读原生保存的历史，恢复后接入结构化事件；只读历史不启动原生服务。Markdown 统一支持标题、表格、任务列表、代码高亮和复制。mermaid 围栏复用已有 Vditor 附带的 Mermaid，按需加载、跟随深浅主题，并在禁止网络和同源访问的沙箱中绘制；语法不完整或错误时保留源码。Markdown 不执行原始 HTML、脚本链接或自动加载远程图片。

必要行为：

- 卡片点击后进入对应会话。终端支持键盘输入、粘贴、滚动和尺寸变化；dsh 保留自己的聊天与操作界面。
- 切换卡片或关闭详情不会终止会话；再次进入仍是同一个原生会话。
- 每个会话有可复制、可收藏的网页链接。刷新和浏览器前进／后退恢复相同视图，不自动启动 Agent 或提交普通草稿；已明确入队的消息依原生状态恢复。
- 终端连接短暂中断能够重连；应有可见的连接状态和合理的输出回放。
- Codex 与 Claude 结构化图形审批仅转发原生请求和用户的明确决定；PTY 兼容路径与 Harness 在各自原生界面处理审批。
- 服务重启会丢失其托管的活进程时，必须显示真实状态；有原生 ID 的会话通过后端恢复命令继续。
- 单个终端停止和服务关闭都会等待原生进程完成回收；停止期间拒绝输入和重启，清理失败仍保留停止屏障。服务收到关闭信号时，会等待自己启动的原生进程和终端树完成回收，再释放数据目录锁；因此重启不会与上一代托管进程并行。原生工具主动脱离的外部任务不在 Dili 的回收范围内。
- 输入只发送至当前选中的会话。多个终端并存时不得串线。
- dsh 的停止操作通过原生接口取消该成员的任务，不应关闭共享 Web 服务或影响其他成员。恢复后尚未附着原生页面的空闲会话没有活动任务，停止按幂等操作处理；事件流暂时无法确认执行状态时显示“未知”。

Codex 与 Claude 提供结构化发送、流式工具和图形审批；dsh-tui 保留 PTY 兼容发送。统一模型／权限设置、Harness 结构化协议、跨后端统一 Diff 和 IDE 能力仍待推进。群组中的「填入」只准备终端输入，由用户进入原生终端提交；结构化图形成员通过原生协议直接发送。

## 7. Fork 语义

Fork 从来源会话可用的原生上下文生成**独立的新会话**：原会话保留，后续输入互不合并，新联系人可独立命名和操作。

- 优先采用后端官方 Fork 命令或接口。
- 首版可以只支持后端可用的最新分叉点，不要求任意历史消息节点。
- 只有取得有效来源原生 ID，并确认后端支持时，才允许原生 Fork。
- 后端不支持原生 Fork 时，禁用该操作并解释；若以后提供摘要新建，应使用不同名称。
- Fork 过程失败应显示错误，不能把一个没有继承上下文的空会话标为成功。
- 创建分支卡片可以先处于“待启动分叉”；原生命令启动、身份确认之前，不显示为分叉已完成，也不能继续从该卡片分叉。
- 新会话原生 ID 可以在启动后确定；等待期间保存的来源 ID 只用于原生 Fork 命令，不能当作新分支的身份。

**会话 Fork 不会自动创建 Git 分支或 worktree。** Claude、Codex 的 Fork 窗口允许填写已有的目标工作目录；dsh 原生 Fork 保留原目录，当前不支持改目录。群组内“从已有联系人 Fork”默认沿用来源目录；需要为 Claude/Codex 指定目录时，可从来源卡片打开 Fork 窗口并选择目标群组。

## 8. 基础群组

### 8.1 群组与成员

群组具有名称、共同目标、成员联系人和持久化消息记录。成员仍是完整会话联系人，具有同样的状态、改名、进入和原生交互能力。

两种加入方式：

1. **在群组中新建**：选择后端，创建归属该群组的新会话。
2. **从已有会话 Fork 入群**：保留原联系人，新分支归属目标群组并记录来源。

“移入群组（Fork）”在本产品中的含义是第二种，不是直接移动原会话，也不是让内外两张卡片控制同一个上下文。群组成员可以再次单独打开，用户纠正后继续参与共同任务。

### 8.2 本轮必须完成的协作闭环

- 展示共同目标与成员状态。
- 用户在群组记录消息、任务说明与结果。
- 明确选择一个或多个成员，为其准备任务或共享消息。
- Codex／Claude 结构化图形模式：通过原生接口直接发送，记录为「已发送」；终端成员先填入终端，用户检查后按回车提交。dsh 通过原生会话接口发送。图形模式执行中或有待回复请求时，不插入新一轮任务。
- 记录收件人及“待处理 / 投递中 / 结果待确认 / 已填入 / 已发送 / 已取消”状态。先持久化投递尝试，再调用原生接口；连接中断、响应丢失或投递中重启会转为“结果待确认”，禁止直接重发。进入原生会话核对后，可确认已收到、确认未收到并恢复待投递，或关闭投递。只有明确未被原生接口接收的请求才能直接恢复待处理。已填入终端不等于 Agent 已收到。
- 能将一个成员的结果显式共享到群组，再交给其他成员继续处理。
- 群组消息可直接“转交为任务”：预填可编辑内容、指定接收人并保留来源链接。创建后仍为待投递；已有草稿须由用户选择保留或替换，转交来源随草稿保存。
- 服务端每页最多返回 200 条群消息及该页的投递摘要；进入群组读取最新页，后续按变更游标增量同步，可逐页读取更早记录。已加载的来源消息直接定位，未加载的来源按消息 ID 单独读取并弹窗展示。展开历史保留阅读位置和草稿，中文输入法选词时不会误触发布快捷键。
- 能在群组内整理最终结果；结果保留成员或消息来源。
- 单独进入成员纠正时，输入仅送达该成员；涉及其他成员的变更由用户显式同步。

首版采用**用户主导的路由**。群消息不默认广播，不让成员自动回复所有消息；自动分工、管理员 Agent、循环对话和自动冲突处理后置。基础群组已经能协作，但不承诺全自动编排。

## 9. 后端能力与适配

| 能力 | 接入原则 |
|---|---|
| 启动与交互 | Codex 原生 app-server 图形对话／终端；Claude 官方 stream-json 图形执行／原生终端交接；dsh 有 dsh-tui 时托管原生终端，否则复用原生 Web 会话 |
| 认证和权限 | 复用原生 CLI 的用户配置与审批流程 |
| 恢复 | 按已安装版本支持的原生命令及会话 ID 实现 |
| Fork | 按已验证的原生能力启用，缺失时明确不可用 |
| 状态 | 结构化接口优先，进程事件其次，终端推断需标明 |
| 群消息投递 | Codex／Claude 结构化图形模式及 dsh 通过原生接口发送；终端模式先填入再由用户提交；分别记录状态 |

Claude Code、Codex、dsh 均为目标后端，但不能把“支持 DeepSeek 模型”当作支持 DeepSeek Harness。不要预设三者具有完全一样的 API、终端行为或会话元数据。

适配器报告原生程序可用性、版本、能力与限制。dsh 通过原生 Web 服务及会话接口适配；Claude 图形模式使用 stream-json，终端使用原生命令与进程级 Hooks；Codex 优先使用原生 app-server 提供身份、Fork、状态、图形输入和审批，并保留连接同一线程的原生终端。旧版 Codex 使用原生命令及完成通知。接入参数只作用于当前托管进程，不改写用户全局配置；未收到原生状态时，使用明确标注的终端推断或未知状态。

## 10. 数据与技术方案

首版采用 Node.js 24、TypeScript、React、Vite、xterm.js、node-pty 与 Node 内置 SQLite。浏览器通过本地 HTTP API 和实时连接访问服务，终端输出与状态同步到页面；dsh 由独立适配器连接原生 Web 服务。

主要实体：

| 实体 | 关键数据 |
|---|---|
| Session | 本工具 ID、后端、名称、工作目录、原生 ID、状态及依据、群组归属、Fork 来源、时间、归档标记 |
| Group | ID、名称、共同目标、创建与更新时间 |
| GroupMessage / Delivery | 群组、正文、类型、来源成员、收件人、填入或发送结果、时间 |
| Event | 会话或群组、类型、必要载荷、时间 |

元数据持久化到 SQLite；终端通过 xterm 状态序列化保存最近 1000 行滚动历史，最多保留 10 个已结束会话的内存画面，重连恢复光标和原生屏幕状态。这些终端快照不会写入磁盘，服务重启后原生历史仍由后端负责。不要默认存储密码或解析用户的认证凭据。真实会话数据与演示数据明确区分。

### 本地运行

环境要求：Node.js 24；使用真实后端时需要分别安装并完成 Claude Code、Codex、dsh 的原生登录。`node-pty` 在没有适用预编译包时需要系统原生编译工具。

已在 Linux（前轮）和 macOS（本轮）运行本地回归；CI 配置覆盖 Node.js 24 的 Linux/macOS 构建、后端与 Chromium 检查。Windows 尚未验收；按 PID 启动时间核对并回收多代进程的增强逻辑目前仅用于 Linux。安装与启动时修复 macOS node-pty helper 的执行权限，启动预检会实际创建一个短生命周期 PTY。

一键启动：

```sh
./start.sh
```

脚本检查 Node.js 24+ 和 npm，并在安装依赖或构建前检查端口和数据目录是否已被占用；已有实例运行时直接退出，保留原实例。检查通过后，在缺少依赖或依赖清单更新时自动安装，然后构建并启动。浏览器访问 `http://127.0.0.1:4317`，终端按 Ctrl+C 正常关闭。可以从其他目录通过脚本的绝对路径启动；工作目录统一为项目目录。

默认只监听本机。如需让局域网设备访问，指定监听所有网卡：

```sh
SESSIONDECK_HOST=0.0.0.0 ./start.sh
```

然后从其他设备打开 `http://服务器局域网IP:4317`。监听 `0.0.0.0` 或 `::` 时，服务接受任意主机名或 IP 的同源访问，无需配置允许列表。开发模式在命令末尾加 `--dev`。

开发模式使用 `./start.sh --dev`，查看选项使用 `./start.sh --help`。已有服务运行时可继续使用原实例；并行开发须指定独立端口和数据目录，例如 `SESSIONDECK_PORT=4327 SESSIONDECK_DATA_DIR=/tmp/sessiondeck-dev ./start.sh --dev`。设置数据目录时建议使用绝对路径。`--dev` 会监听后端文件变化并重启开发服务，重启会结束该实例托管的 Agent 进程和 Shell 终端，持续任务应在普通启动模式下运行。

独立端口和数据目录不会隔离同一仓库中的依赖。如果需要更新依赖或执行 `npm install` / `npm ci`，应在单独的 checkout 或 Git worktree 中开发，让运行实例保留自己的 `node_modules`。

开发模式若提示 `ENOSPC: System limit for number of file watchers reached`，可使用 `CHOKIDAR_USEPOLLING=1 ./start.sh --dev` 改为轮询文件变化；默认启动不需要文件监听。

首次安装或在独立开发 checkout 中手动启动：

```sh
npm install
npm run doctor
npm run dev
```

浏览器访问 `http://127.0.0.1:4317`。生产构建与运行：

```sh
npm run build
npm start
```

生产前端先在临时目录完成构建，成功后发布资源，最后原子替换 `index.html`。旧的带哈希资源继续保留，已经打开的页面仍能加载所需模块；构建失败不会清空正在使用的前端。`npm run build` 不重启后端；后端代码变更需等当前任务结束后，再主动重启服务加载。

```sh
npm test
npm run verify
```

`doctor` 检查 Node、PTY、目录权限与原生命令，不检查登录凭据或调用模型；`verify` 依次运行类型检查、后端测试和浏览器验收，前端生产构建由浏览器验收在独立目录完成。

浏览器验收使用独立端口、临时演示数据和临时前端构建目录，不复用或停止正在使用的服务，也不安装项目依赖。它会自行完成生产构建，无需提前执行 `npm run build`。首次需要安装 Chromium：

```sh
npm run test:web
```

默认测试端口为 `4337`；若被占用，可使用 `SESSIONDECK_TEST_PORT=4339 npm run test:web`。测试拒绝使用正式服务默认端口 `4317`。

可选原生启动检查使用临时配置和工作目录，不输入提示词，不执行模型任务：

```sh
npm exec tsx scripts/native-cli-smoke.ts
```

真实原生程序的隔离工作流验收使用确定性的本机模型服务，不消耗模型额度。dsh 使用独立配置与外网连接拦截；Claude 与 Codex 使用独立配置及 Linux 网络命名空间，因此需要 `unshare` 和可用的用户命名空间：

```sh
npm run test:smoke:codex
```


默认应用数据目录：`~/.local/share/sessiondeck`，可通过 `SESSIONDECK_DATA_DIR` 指定。数据目录使用独立 `instance-lock.sqlite` 的独占事务锁，支持长路径及目录别名，进程退出或被杀后由操作系统释放；不要删除正在使用的锁文件。升级本次锁机制变更时，应先正常停止旧版服务再启动新版。演示模式用于验证界面与组织流程，不能证明真实后端接入成功；使用独立目录启动：

```sh
SESSIONDECK_DEMO=1 SESSIONDECK_PORT=4338 SESSIONDECK_DATA_DIR=/tmp/sessiondeck-demo npm run dev
```

可选设置：

| 变量 | 默认值与作用 |
|---|---|
| `SESSIONDECK_PORT` | `4317`，Web 应用端口（也接受 `PORT`） |
| `SESSIONDECK_HOST` | `127.0.0.1`，Web 监听地址（也接受 `HOST`）；设置为 `0.0.0.0` 或 `::` 可接受局域网访问 |
| `SESSIONDECK_DATA_DIR` | 本地元数据目录，同一目录只允许一个服务实例 |
| `SESSIONDECK_CLIENT_DIR` | 默认仓库下的 `dist/client`；前端构建输出及生产静态资源目录，构建与启动须使用同一值；浏览器测试自动使用临时目录 |
| `SESSIONDECK_TEST_PORT` | `4337`，仅用于浏览器验收；需为未占用端口，不能为 `4317` |
| `SESSIONDECK_DSH_PORT` | `4318`，按需启动的 dsh 原生 Web 服务 |
| `SESSIONDECK_CODEX_PORT` | `4319`，按需启动的 Codex app-server；`0` 自动选择空闲端口 |
| `SESSIONDECK_CLAUDE_BIN` / `SESSIONDECK_CODEX_BIN` / `SESSIONDECK_DSH_BIN` | 可选原生程序绝对路径，未设置则从 `PATH` 查找 |

Codex app-server 只监听本机并使用随机访问令牌。令牌文件仅当前用户可读，正常关闭后删除；令牌不会发送给网页或出现在命令参数中。

元数据可在线备份，不用停止正在运行的会话：

```sh
npm run backup
npm run backup -- --output /path/to/new-backup.sqlite
```

图片文件持久保存在数据目录的 `chat-images/`（图形附件）和 `terminal-images/`（原生终端附件），避免原生恢复引用失效。当前没有自动垃圾回收或磁盘配额，清理前应确认原生历史不再依赖文件。数据库备份不包含图片文件，迁移需另外备份这两个目录并保留原生历史中的路径关系。

默认写入当前数据目录的 `backups/`；备份包含联系人、群组、群消息、投递记录和活动，**不包含三种原生工具自己的历史或凭据**。命令使用 SQLite 一致性备份，不会改变运行状态，现有目标文件不会被覆盖。

恢复时先停止 Dili，把备份文件放入一个新的空目录并命名为 `sessiondeck.sqlite`，再用 `SESSIONDECK_DATA_DIR=/path/to/restored npm start` 启动；这样保留现有数据目录供回退。原生会话仍需原有原生历史及可用的工作目录。服务恢复后所有托管进程均显示未运行，不会自动重新执行任务。

运行命令与能力边界需随实现同步维护。真实后端的登录、额度和平台可用性由本地环境决定。

## 11. 本地边界

- 服务默认只监听 `127.0.0.1`，首版面向本机单用户浏览器。
- 本工具不默认上传会话或启用云同步；原生 Agent 仍按其配置连接各自服务。
- 浏览器写操作和终端连接需校验来源，防止任意网站控制本地会话。
- 本地开发、测试和提交不授权创建、删除、推送或修改任何云端仓库；具体云端操作必须另获明确授权。
- 不默认替后端批准操作，不通过关闭安全确认换取自动化。

### 11.1 身份与权限

| 身份 | 如何获得 | 能做什么 |
|---|---|---|
| 本机所有者 | 从 `127.0.0.1` 本机端口访问，无需密码 | 全部功能，包括设置密码与远程访问 |
| 远程所有者 | 在远程地址输入所有者密码 | 全部功能，除修改密码、远程配置和原生回调（仅限本机） |
| 只读分享 | 打开分享链接并留下名字 | 仅这一个会话：状态、终端输出（输入被丢弃）、对话记录、文件与 diff |
| 可协作分享 | 同上 | 在只读基础上：终端输入、图形对话、审批、启动与停止 |

- 每个 API 在 `server/access.ts` 中登记权限，未登记即拒绝；`server/auth.test.ts` 枚举所有已注册路由，漏登记会让测试失败。
- 分享只能访问一个会话：状态与实时推送按会话过滤，其他联系人、群组、底部 Shell、目录浏览、新建与分享管理一律拒绝。
- 可写分享即完全信任：Agent 能在这台电脑上执行命令，只分享给信任的人。分享期间的操作以对方填写的名字记录在会话活动中。
- 密码用 scrypt 加盐保存；设备凭证与分享令牌只保存哈希。登录失败按来源和全局限速。更换密码会退出所有远程设备；撤销分享或设备会立即断开其终端与实时推送。
- 分享链接的令牌放在 URL 的 `#` 之后，不会出现在服务器访问日志中；打开后立即从地址栏移除。

### 11.2 远程访问（自有域名与服务器，电脑无需公网 IP）

```
浏览器 ──HTTPS──▶ 服务器 Caddy（自动证书）──▶ 服务器 127.0.0.1:17317
                                                ▲ SSH 反向隧道（由电脑主动发起、断线自动重连）
                                     电脑 127.0.0.1:<远程端口>（必须登录）
```

1. 在本机打开「连接与能力 → 远程访问与安全」，先设置所有者密码。
2. 服务器：把域名解析到服务器 IP，安装 Caddy，写入页面上生成的配置并 `sudo systemctl reload caddy`。
3. 电脑：确认可以免密 `ssh 用户@服务器` 登录（隧道使用 BatchMode，不会弹出密码输入）。
4. 填写公开地址、服务器地址、SSH 用户，点「启用远程访问」，状态变为「已连接」即可。

- 远程请求使用独立的监听端口（默认 Web 端口 + 1，可用 `SESSIONDECK_REMOTE_PORT` 指定），只绑定本机回环；隧道只转发这个端口，因此"来自 127.0.0.1"不会被当作本机所有者。
- 服务器端隧道只绑定 `127.0.0.1`，外网只能经过 Caddy 的 HTTPS 访问；TLS 在你的服务器上解密。
- DeepSeek Harness 的原生网页界面只在本机可用，远程暂不支持。

## 12. 交付阶段与验收

| 阶段 | 必须交付 | 验收场景 |
|---|---|---|
| A：联系人 | 三后端入口、卡片、改名、状态、原生终端或 Web 会话、持久化 | 新建会话，改名后刷新保留；切换会话不丢失活进程；输入不串线 |
| B：Fork | 原生能力探测、分叉与来源关系 | 对支持的后端分叉；新旧上下文独立；不支持时原因清晰；失败不冒充成功 |
| C：基础群组 | 目标、成员、新建入群、Fork 入群、独立私聊、消息/任务/结果及定向投递 | 创建跨后端群组，向指定成员准备或发送任务，私聊纠正，将结果共享给另一成员并记录汇总；填入终端不能误标已发送 |

## 14. 日常使用与恢复

### Codex 沙箱在 Ubuntu 24.04 上无法启动

症状：Codex 的每条命令都在执行前失败，报 `bwrap: setting up uid map: Permission denied`。原因是 Ubuntu 23.10+ 默认 `kernel.apparmor_restrict_unprivileged_userns=1`，没有 AppArmor 配置文件的程序不能创建用户命名空间，而 Codex 的 Linux 沙箱正是 `/usr/bin/bwrap`。这与 Dili 无关，在普通终端里直接运行 Codex 也一样。在终端执行一次（需要 sudo）：

```bash
scripts/fix-codex-sandbox.sh
```

它给 bwrap 写入一个只授予 `userns` 的 AppArmor 配置文件并加载，沙箱本身保持开启；已打开的 Codex 会话直接恢复，不用重启任何服务。

### 远程重启服务

服务可以作为 `systemd --user` 单元运行，这样在任何地方（包括远程打开的 Dili 底部 Shell）都能重启它，重启电脑后也会自动拉起：

```bash
scripts/install-service.sh    # 一次性：安装单元并启用 linger，不动正在运行的实例
scripts/restart-service.sh    # 每次重启：在独立会话里后台执行，发起它的终端被关闭也不影响
```

重启会停止所有正在运行的 Agent 会话（它们是服务的子进程）；联系人保留原生会话 ID，进入卡片即可恢复。脚本只会停止本项目、监听该端口的 Dili 进程，不会按端口误杀其他程序。手动查看：`systemctl --user status dili`，日志：`journalctl --user -u dili -f`。

用户服务名为 `dili.service`。旧版本安装的 `sessiondeck.service` 仍会被识别：设置页「迁移到 dili.service」、`dili service enable` 或重新执行 `scripts/install-service.sh` 都会启用新单元并停用旧单元，但不停止正在运行的实例；`scripts/restart-service.sh` 会把旧单元托管的实例切换到 `dili.service`。



**先创建一张联系人卡片。** 选择后端、名称，点击「浏览」选择已有工作目录，或粘贴路径／`file://` 链接，进入后启动原生会话。卡片显示最近输入，目录旁按钮可直接复制完整路径。Codex 默认打开「图形对话」，直接输入发送，回复支持 Markdown 和代码复制，审批及提问出现在对话中；随时可切换「原生终端」。Claude 结构化图形模式支持流式回复、文字／图片、审批与问题，生成中发送进入队列；切换原生终端需空闲并确认交接。已安装 dsh-tui 的 Harness 可在记录页直接发送文字或图片。无 dsh-tui 时使用 Harness 原生 Web。顶部「打开终端」会显示 VS Code 风格的底部终端，可添加多个独立 Shell 标签并左右分屏，同时保留当前会话。首次登录、Harness／PTY 兼容路径的审批及图形界面尚不支持的确认在原生终端处理。关闭详情只离开视图；Codex「停止生成」中断当前一轮并暂停队列，「停止会话」结束托管运行。

**让几个会话协作。** 创建群组并写下共同目标，添加新成员或 Fork 已有会话。写一条任务，选择收件人，再处理每个成员的待投递项。Codex／Claude 结构化图形成员和 dsh 的“发送到会话”通过原生接口执行；终端成员的“填入”只准备输入，需要进入该成员按回车。群内没有自动广播。

**处理连接问题。** 卡片状态代表 Agent 的执行状态，终端“已连接”只代表浏览器通道可用。浏览器断线后会自动恢复；服务重启后，卡片保留，但原生进程需要手动恢复。使用 `npm run doctor` 检查本地环境，进入“连接与能力”重新检测原生命令。端口冲突时设置对应的端口变量，不会接管或停止占用端口的其他服务。

**遇到请求超时。** 启动、停止或 Fork 需要等待原生程序响应，页面会保留更长的等待时间。若仍提示超时，先刷新状态并查看是否已经完成，再决定重试。投递显示“结果待确认”时，进入原生会话核对，再选择已收到或未收到；不要重复提交尚未核对的任务。

**保存数据。** 联系人名称、群组和投递记录保存在本机 SQLite；使用 `npm run backup` 生成一致性备份。后端自身的对话历史仍保存在各原生工具中。群组草稿保存在当前浏览器；Codex 私聊草稿和待确认标识保存在当前标签页，均不包含在服务器数据库备份里。

# 邀请码远程配对

管理员打开 `https://discoverpaw.com/connect/`，使用服务器上的管理密钥生成一次性邀请码。生成时可选择中继白名单中的访问域名，默认是 `discoverpaw.com`。本机 Dili 在“连接与能力 → 远程访问”粘贴邀请码并填写设备名称，服务会自动安装并启动官方 frp 客户端，生成可复制的设备链接。手机打开设备链接后使用 Dili 所有者密码登录。 支持从其他网站点击设备链接进入登录页；仅对工作台入口的顶层页面跳转放行，跨站 API、iframe、终端连接和修改请求仍受到来源校验。

中继服务运行在 `paw` 的 `sessiondeck-relay.service`，frp 服务运行在 `sessiondeck-frps.service`；两个服务只监听回环地址，Caddy 通过 `/connect/` 和 `/~!frp` 转发。管理密钥保存在 `/var/lib/sessiondeck-relay/admin.token`，不会写入仓库或 URL。可通过 `SESSIONDECK_RELAY_DOMAINS=discoverpaw.com,example.com` 配置额外域名白名单；这些域名必须在 Caddy／DNS 中指向同一个中继服务。现有 SSH 远程方式仍可在高级设置中使用。

邀请码可选 1 小时、24 小时、7 天或永不过期，每个邀请码只能开通一台设备。有效期只限制首次兑换，已配对设备不会在邀请码到期后断开；需要停用时撤销设备。同一次配对遇到网络错误可用原邀请码重试，保存的兑换标识防止重复创建设备。

首次配对依次显示准备客户端、兑换邀请码和启动连接。客户端下载优先使用管理员指定的镜像、邀请码所在中继提供的安装包，再回退到官方 GitHub 与备用镜像；每个源最多等待 30 秒，所有源合计最多 90 秒，安装包必须通过固定 SHA-256 校验。安装失败不消耗邀请码，失败后显示错误并允许重试。已有配对显示远程连接状态，连接失败时可保存并重连。也可通过 `SESSIONDECK_FRPC_PATH` 指定本机已有客户端。

更新中继时运行 `npm run build:relay` 和 `npm run prepare:relay-clients`，将 `dist/relay/relay.mjs`、`dist/relay/index.html` 及 `dist/relay/clients/` 同步到服务器安装目录。客户端安装包目录默认位于管理页面文件旁的 `clients/`，可通过 `SESSIONDECK_RELAY_CLIENTS_DIR` 覆盖。然后重启 `sessiondeck-relay.service`；保留数据目录中的 SQLite、管理密钥及插件密钥，FRP 配置未变时无需重启 `sessiondeck-frps.service`。

转发配置见 `relay/public.caddy`：设备路径必须使用 `route` 保持先鉴权、后路径改写的顺序，否则 Caddy 默认排序可能让有效链接返回 410。已有站点若启用全站 `encode`，需将响应类型限制为 HTML/CSS/JavaScript/JSON/SVG，排除 `text/event-stream`，避免实时状态被压缩缓冲。修改后用 `caddy validate` 检查，再 reload Caddy。
