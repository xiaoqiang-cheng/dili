# Dili 图形工作台架构改造方案

更新日期：2026-10-23。

## 产品目标

Dili 的图形界面最终应支持日常会话工作，不要求用户为正常输入、查看输出、审批、回答 Agent 问题、切换会话设置而打开原生终端。平台暂时不支持的操作必须在图形界面明确说明，并提供可靠的替代路径；不能把不支持的能力伪装成已支持。

Dili 统一联系人、群组、任务交接、消息呈现、草稿、发送状态和跨设备工作流。各 Agent 继续拥有其模型执行、身份认证、工具、权限策略和原生会话格式。优先调用 Agent 官方结构化接口、SDK 或 ACP；兼容 PTY/日志读取只作为有明确限制的后备路径。

## 架构目标

```text
联系人、群组、任务中心、远程工作台
                 |
统一图形交互：输入、消息、活动、审批、问题、设置
                 |
平台无关的会话和交互契约
                 |
Agent 适配器注册表
   |             |             |
Codex           Claude        Harness / ACP / 后续平台
                 |
官方 Agent 执行器、协议或受支持的原生界面
```

图形 UI 只消费公共事件和能力声明，不依据 Codex 专属数据类型判断消息行为。适配器负责原生身份、消息映射、执行控制和能力差异。新增平台应实现契约，而不需要修改所有 UI 组件。

## 交互契约

基础会话能力：发现、创建、恢复、Fork、读取分页历史。

对话能力：发送带幂等 ID 的文本和附件，订阅带修订号的增量事件，读取完整快照，停止当前轮，核对未知发送结果。

可选交互能力：回答审批、回答用户问题、读取和修改当前会话配置（模型、权限模式、推理等级等）、生成中补充输入、接入同一会话的原生终端。

适配器按运行时版本和会话执行模式报告能力状态：`supported`、`unsupported`、`experimental` 或 `native_required`，并提供原因。不得把平台名称等同于其所有安装版本的统一能力。

公共事件至少包含：消息新增／更新／完成、工具调用及结果、审批请求、用户问题、配置变化、回合状态、错误和历史截断。原生消息 ID、请求 ID、回合 ID 与来源事件 ID 必须保留，用于去重、重连对账和审计。

## 执行者与原生终端

每个会话同一时间只能有一个写入执行者。会话记录应能够表达执行模式（图形 Agent 协议、原生 PTY、原生 Web 或只读历史）、当前执行者身份和连接状态。图形执行器与 TUI 不得并行写入同一原生会话。

优先支持 Agent 明确提供的同实例交接。若协议只支持恢复持久会话 ID，不代表可以接入原运行进程。不能可靠交接时，产品应执行有确认的停止／暂停与恢复流程，或创建新的交接会话；不得声称两种模式控制同一个实时实例。

## 跨平台与模型交接

同一平台的原生会话内模型切换优先使用原生配置接口。若不支持，创建新的 Fork／交接联系人。

跨平台交接创建独立目标会话，来源会话保持不变。用户可审阅交接摘要、工作目录、相关消息和 Git 状态；界面显示已传递与未传递的上下文。默认不把整份超长对话隐式塞入目标上下文。

### 阶段 1：Codex 作为结构化适配器基线

- 将现有 app-server 的流式消息、历史、审批、问题、停止和设置能力映射到公共契约。
- 将公共聊天 API 和 UI 从 Codex 专属名称改为 Agent 通用命名，保留现有 HTTP 路径兼容。
- 补充断线、服务重启、事件重复和未知发送结果的统一恢复测试。
- 验收：输入只出现一条；流式消息在重连后不丢不重；审批和提问可在图形界面完成。

### 阶段 2：Claude 图形执行路径验证与接入

- 评估现有 `ClaudeChatBridge` 的官方协议兼容、流式、工具、审批、问题和配置覆盖。
- 明确图形执行器与交互式 TUI 的身份关系；实现单写入者约束与可恢复交接。
- 不把尚未验证的 stream-json 执行路径与 TUI 宣称为同一实时实例。
- 验收：新会话和已导入会话的创建／恢复、中文输入、附件、流式回复、工具审批、用户问题、模型／权限设置和恢复路径均有真实 CLI 版本记录。

### 阶段 3：Harness 与 ACP

- 优先使用 Harness 已公开的会话 API 或其原生 Web UI 能力。
- 探测 ACP 的初始化、会话恢复、配置选项、附件及权限交互；逐项映射，缺少的能力如实报告。
- 验收：适配器契约测试通过，并记录可支持的版本范围和原生入口。

### 阶段 4：新增平台扩展机制

- 先用内置适配器验证扩展点，再定义外部适配器清单、权限边界、升级策略和兼容版本。
- 外部适配器具有进程执行、文件访问和会话控制权限，未设计隔离与信任模型前不启用任意动态插件。
- 验收：新增一个平台不需修改通用聊天组件、会话状态机或已有适配器。

## 适配器契约测试

每个适配器必须明确验证：创建和恢复、Unicode／多行发送、附件声明、流式及历史一致性、重复事件去重、审批与问题回答、停止、模型／权限设置、结果不确定时禁止盲目重试、网络断开恢复、服务重启恢复，以及图形与原生模式交接。无法支持的能力应有显式负向测试。

自动化测试使用隔离 CLI fixture；发布前另记录真实 CLI 版本和真实会话验收。模拟协议通过不能替代真实 Agent 兼容性验证。

## 当前代码与首批改造

- `server/codex.ts`：现有 app-server 客户端及 Codex 执行能力。
- `server/chat-api.ts`：通过 `registerAgentChat` 使用 `AgentChatAdapter` 和按 Backend 注册的适配器表；HTTP 路由保持兼容。
- `server/agents/chat.ts`：平台无关的聊天适配器契约与注册表。
- `shared/chat.ts`：定义 `AgentChat*` 平台无关类型，同时保留 `CodexChat*` 兼容别名。
- `server/claude-chat.ts`：Claude 官方 stream-json 适配器，由图形模式启动；提供实时正文、工具、审批、问题、图片和停止。TUI 另走 PTY，不能并行写同一联系人。
- `server/dsh.ts`：Harness 会话及原生 Web 集成；图形聊天采用独立适配方案评估。
- `client/AgentChatPane.tsx`：Codex 与 Claude 共用的图形交互面板，消费公共聊天契约；保留现有草稿存储键以保护未发送内容。

## 2026-10-23 实施记录：Claude 结构化执行

- `Session.executionTransport` 将执行通道与显示偏好分开，区分 structured / pty / web。
- Claude 图形启动使用已安装 CLI 的 stream-json，保留原生认证、配置、权限和历史；不引入第二套模型 API 或密钥。
- 运行中的 Claude 切换执行方式要求空闲、无审批、显式 `handoff: true`。UI 先解释交接并确认，后端退出旧执行者后才启动新执行者；只读分享不触发交接。
- 启动、停止、异常退出、服务关闭和群组投递均接入 Claude 执行器；空会话与 Fork 初始化身份持久保存，发送成功回执不冒充历史已落盘。
- 已存在的 PTY 联系人不会在页面刷新时被自动替换。图形视图允许先只读历史；用户明确切换后才建立结构化执行。
- 仍待完成：完整运行时能力声明、Claude 长历史分页、更多 CLI 版本兼容、Harness / ACP 适配。此阶段不宣称所有平台已能完全替代原生终端。

## 2026-10-23 实施记录：统一会话设置

- 公共设置契约返回原生模型列表、当前模型、权限模式、版本令牌和不可修改原因；界面共用设置对话框，不恢复 Codex 专属模型输入框。每次只修改一个字段，避免跨字段半成功。
- Codex 使用安装版本生成的 app-server 协议：`model/list`、start/resume 的实际设置、`thread/settings/update` 与 `thread/settings/updated`；每次读取和提交后均通过无覆盖参数的 metadata-only resume 回读实际设置与原生空闲状态。读取保留自定义审批策略；用户明确选择预设时只切换审批策略／审核者，不隐式改变沙箱及文件或网络权限。官方网页本轮返回 403，接口依据本机生成协议和真实 CLI 隔离验证。
- Claude 使用原生 initialize 的 models/current_permission_mode 和 set_model/set_permission_mode 控制回执；原生未报告当前模型时显示未报告。设置限当前图形执行器，交接／重开后重新读取原生配置；不写用户全局配置。
- 仅所有者可修改；分享可查看。后端以真实活动轮次、审批、提交锁和设置版本检查空闲，拒绝过期面板和并发修改。失败不伪装成功，重新读取后允许重试；不支持的旧 CLI 明确报错。
- 验收覆盖两平台真实控制参数、原生拒绝、过期版本、生成中禁用、只读权限、手机面板及草稿保留；真实 CLI loopback 验证下一轮使用新模型。

### 使用与边界

- 工具栏「会话设置」及输入框 `/settings`、`/model`、`/permissions` 打开同一个面板；模型选项来自当前原生 CLI，不提供任意模型字符串输入。打开面板保留原草稿，单独提交快捷命令不会作为任务发送。
- 输入区下方独立模型／权限按钮复用同一设置 controller 和后端接口，按需读取原生选项、每次明确应用一个字段；与完整面板同步显示确认值。失败后清除可提交快照，要求回读；连接身份改变使旧请求失效，避免晚到响应污染新会话。保存期间阻止发送。
- `/` 菜单只列已接入的设置命令，提供图标、用途说明、前缀筛选及键盘选择；已列命令不作为任务文本发送，未列命令尚未接入原生控制。浮层通过 Portal 脱离输入区滚动裁切，按界面缩放与可视窗口定位，适配手机和全屏；输入法候选确认不触发命令。
- Claude 首批提供默认审批、自动接受编辑及计划模式；不承诺所有原生权限模式均可切换。原生只返回模型别名时保留实际回执，未报告或确认结果不确定时显示未知，不猜测有效设置。
- 原生明确拒绝保留已确认状态；超时或缺少回执不显示成功，界面要求刷新确认。版本令牌与连接身份阻止过期面板继续修改。
- 当前设置不是 Dili 的持久配置；重开执行器或重新应用联系人初始 Auto 预设后可能变化。每次进入面板以原生报告为准。推理等级、完整能力矩阵和 Harness 设置不在本轮支持范围。

## 2026-10-23 已实现：Claude 历史分页与恢复

- 继续复用 Claude 自己的 JSONL 历史，不复制会话数据库、不启动 CLI 读取旧消息。每次按固定字节窗口向前扫描，最多返回 40 条消息，独立限制单条和整页文本；工具或巨型图片记录可返回空页，但游标必须推进。
- 游标经服务端签名并绑定原生身份、文件 inode、快照长度和头部指纹；允许后续追加，拒绝篡改、跨会话和被截断／替换的文件。分页只读，不改当前任务和审批状态。
- 流式临时消息在原生最终消息到达后与保存 UUID 对账，客户端能识别被替换的临时项，避免加载旧历史后重复显示。用户消息直接复用保存 UUID。
- 公共面板继续保留加载旧消息时的阅读位置；服务实例变化后清除旧游标，忽略旧实例尚未完成的分页结果。真实账号、多版本与跨进程异常写盘仍需单独验收。
- 每次扫描窗口最多 2 MiB，单条文本最多 24,000 字符、整页最多 512,000 字符；只接受完整行，图片仅保留数量与占位，不返回图片字节。大记录可能省略，不把分页视为全量原生上下文导出。
- 实时快照裁剪旧项时刷新磁盘分页游标，避免新生成消息离开快照后无法继续回看。分页结果不覆盖正在执行的轮次、工具或审批。
- 真实 Claude 2.1.308 的 Fork 在首次输入前没有独立日志，先读取源会话有界一页并映射为子会话 UUID；不复用源游标。首次结果到达后读取子日志游标。停止尚未输入的 Fork 保留当前进程内的继承视图；未写盘的身份与源关系仍由现有联系人恢复流程负责。

### 此增量验收

- `npm run verify`：类型检查通过；服务端 262 项通过、1 项跳过；隔离浏览器 171 项通过。
- 最后补充非 ASCII 游标签名校验后，历史专项 27 项通过，类型检查与 diff 检查通过。
- 真实 Claude Code 2.1.308 loopback 烟测通过，额外确认 Fork 首次发送前显示继承历史、停止后保留，以及继承 ID 与最终保存日志一致。真实云端账号、多版本和手机远程体验保留待办。
