## 如何避免再次漂移

1. **一处负责一类事实。** README 面向新用户，产品规格描述现状，TODO 跟踪余项，方案文档区分目标和实施。安装命令、运维步骤不在每份文档里复制一遍。
2. **行为变更同时更新文档。** 修改功能时，先更新负责该行为的文档及 TODO；改变对外承诺、入口或安装方式时，再同步 README。不能只在 WORKLOG 中记下已实现，却让规格继续写“待做”。
3. **把复合待办拆开。** 同一条里的部分能力已实现时，拆成已完成基础与剩余项；不因部分完成把整项勾选。
4. **实现、验证、部署分别写。** `[x]` 表示该条所述工作完成；本地 fixture、真实 CLI + loopback、真实账号和公网部署各注明范围。CI 已配置不等于云端通过，本地修复不等于线上已更新。
5. **保留历史，指向现状。** 不回写旧 WORKLOG 的测试数量；旧方案或调研在顶部标注日期与适用范围，链接到当前说明。README 不陈列不断过期的测试计数和 CLI 版本号。
6. **交付前检查链接与说法。** 核对相对链接、锚点、资源路径、命令及支持矩阵。截图与布局示意明确区分，规划中的功能不作为现有卖点。

本轮整理只修改文档和说明插图，不改变运行行为；也未重新验收公网部署或外部服务价格。
