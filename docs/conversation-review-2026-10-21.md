# 会话交互整体 Review（2026-10-21）

后续更新（2026-10-23）：下文保留 10 月 21 日的阶段记录。Claude 图形模式现已改用官方 stream-json，支持实时正文、工具和图形审批／提问；与 TUI 通过同一持久会话进行空闲交接。当前实现和边界见 [Claude 图形会话](claude-streaming.md)及[架构方案](graphical-workbench-architecture.md)。

## 结论

本轮完成三平台消息排版统一、会话标题栏与副工具栏合并、Claude／dsh-tui 图形直接发送，以及可编辑的补充消息队列。原先只有 Codex 能直接发送，是其他后端适配停留在「记录读取＋终端填入」阶段的实现缺口，并非图形界面必须这样设计。

## 已实现

| 范围 | 现在的行为 |
| --- | --- |
| 标题栏 | 名称、视图切换、目录、刷新、终端操作、全屏和关闭共用一行；窄屏将次要操作收进会话工具。 |
| 消息排版 | 三平台共用阅读宽度、间距、右侧用户消息和通栏助手 Markdown。 |
| Claude／dsh-tui 发送 | 输入文字或图片后点击发送，留在图形界面；保留多行，中文候选确认不误发。 |
| 生成中补充 | Codex 复用 turn/steer；Claude／dsh-tui 交给原生输入协议，由原生决定消费时机。 |
| 待发送队列 | 生成期间可加入队列，支持文字、图片、编辑、取消及立即发送；最多 10 条。 |
| 自动释放 | 原生确认本轮结束后逐条提交；不以终端静默或推断状态代替完成事件。 |
| 异常恢复 | 请求持久去重；不确定结果先查询，禁止自动重复提交；保护发送期间新写的草稿。 |
| 暂停 | 原生身份改变、拒绝或结果不确定时暂停对应消息；Codex 停止生成先暂停队列。 |

## Review 发现及修复

- 异步获取原生连接信息期间，快速入队可能拿到后来编辑的草稿。改为点击时捕获待发快照，完成后仅清除相同已发内容。
- 输入区较矮且有图片时，附件区域可能覆盖发送结果核对按钮。修正收缩规则，保持核对和错误操作入口可达。
- 原生终端全屏复用父级布局，避免为全屏重建终端与连接；窄屏工具支持 Escape 关闭和焦点恢复。
- 明确区分「本轮结束后排队提交」与原生「下一次工具调用后提交」，界面没有承诺不存在的统一时机。

## 验证

- 类型检查与 git diff 空白检查通过。
- 服务端完整测试：232 项通过，含真实 PTY 输入 fixture、去重、审批状态变化、并发输入、终端替换和图片独立粘贴。

- 随后新增「停止生成后队列保持暂停，刷新不自动续发」专项，1 项通过；不将其称为再次执行了 142 项全量回归。
- 已查看桌面直接发送、补充消息队列、手机单行标题及 200% 缩放截图。

## 保留的边界

- 本轮的新直发路径通过 PTY／协议 fixture 和浏览器验证，尚未对真实 Claude／Harness 模型完成端到端验收。上传成功不等于模型确认收到图片。
- Claude／dsh-tui 的回复来自原生日志轮询，完整结构化工具流与图形审批仍待接入；审批继续在原生终端处理。
- 未安装 dsh-tui 时，Harness 继续使用其原生 Web 界面，此次共享输入区和队列不替换原生 Web。
- 队列在图形会话面板打开时自动推进，离开暂停；重新进入且原生空闲时恢复。当前标签页的 sessionStorage 支持刷新恢复，不承诺关闭标签页后保留。
- 群组的「填入终端」仍是准备输入，由用户检查后提交，不与私聊的新直发流程混淆。
- 后续应优先验收不同 CLI 版本的多行／图片／生成中补充输入，再扩展 Claude／Harness 的结构化交互。

## 更新生效

前端通过原子构建发布，保留旧哈希资源，刷新即可看到新布局。新发送能力需要后端正常重启；本轮没有停止或重启承载当前会话的正式服务。

应从 Dili 之外的独立终端执行仓库中的 `./scripts/restart-service.sh`，重启会结束当前托管的 Agent 和临时 Shell，联系人保留原生 ID 供恢复。不要从当前被托管的会话中自行执行重启。此次仅本地提交与集成，无云端 push 或 tag。
