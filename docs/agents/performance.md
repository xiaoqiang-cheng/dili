# 性能与资源上限

| 对话读取短缓存 | `server/conversation.ts` | 1.5 秒内复用，最多 256 个会话 |

| Codex 首屏 | `server/codex.ts` | 最近 20 轮，失败缩小为 5 轮、1 轮 |

| 终端 WS 背压 | `server/index.ts` | 单连接 2 MiB 积压即断开 |

| Markdown 分块 | `client/Markdown.tsx` | 超过 4000 字符按标题/围栏分块 |

## 渲染上限

- 联系人列表超过 `CONTACT_RENDER_STEP` 时只渲染前 N 条，提供“显示更多”，并显示“已显示 X / 共 Y”。
- 对话记录默认只渲染最近 `MESSAGE_RENDER_LIMIT` 条；更早的消息需要点“显示更早的消息”，避免无限 DOM。
- 长 Markdown 按空行 + 标题/围栏切块（`client/markdown-blocks.ts`），避免一段超大文档阻塞主线程；未闭合的代码块保持整块。
- 代码高亮 `rehype-highlight` 按需动态加载：只有消息里出现围栏时才加载，没有代码的消息不付这份体积。

## 轮询与隐藏页

- 联系人状态由 SSE 推送；只有历史预览按需读取。
- 会话历史轮询：运行中 3 秒、空闲按事件触发；页面隐藏时暂停，恢复可见时补一次。
- 全局时钟、群组历史、群成员实时预览、底部终端列表和 watchdog 在隐藏页暂停；SSE 连接保持，恢复可见时各补一次。
- 不要在前台不可见时做文件监听或全量刷新。

## 排查

- `GET /api/debug` 提供进程、修订、补发窗口、连接、会话和终端的只读快照；界面入口在“更多 → 运行诊断”，先看它再猜。
- 性能问题先区分：网络（SSE 积压）、服务（历史扫描、SQLite）、渲染（DOM 数量、高亮）。
- 加缓存前先问失效条件；状态、权限和分享视图不能缓存到过期。

## 分享与图形会话首屏（2026-11-02）

- 图形客户端通过 `GET /chat?preferSnapshot=1` 请求已有原生快照；身份匹配且有消息时先返回，历史读取继续在后台执行并经既有修订事件更新。普通 `/chat` 保留等待历史完成的语义。
- 快照仍通过 `running && ready && connected` 校验连接状态；缓存正文不能作为发送、审批或设置已就绪的依据。没有快照的冷启动仍需等待原生读取。
- 群分享使用 `useGroupHistory`，按群更新时间读取增量，重连时补齐；不再因为任意全局状态事件重取整包群消息。
- 契约测试人为挂起历史读取，确认已有快照首屏不会被阻塞。这是等待链路验证，不代表真实长会话的端到端延迟基准。

## 远程历史切换（2026-11-02）

- 群聊首屏改为最近 40 条；显式向前翻页和增量批次仍为 200 条，保留原游标与消息修订语义。不截断或删除历史正文。
- `historyRefresh` 串行读取并合并读取期间的更新通知；群更新时间变化不再废弃已在传输的响应，只有导航或实例变化取消结果提交。
- `useGroupHistory` 的缓存仅存在当前 hook 内，按实例和群 ID 隔离，最多 8 群／约 200 万字符／10 分钟，单群超过 50 万字符不缓存；分享页与所有者页面不共享缓存。
- 单会话 `preferSnapshot` 在原生快照缺失时可返回身份一致、10 分钟内的服务端阅读快照；强制清空 connected、activeTurnId 和 requests，后台通过既有修订通道恢复实时状态。无快照的首次读取仍等待原生读取。
- 已用隔离浏览器测试阻塞远程刷新，验证切回群聊仍显示缓存历史；这不代表真实公网链路的延迟承诺。后续远程基准需分别测 TTFB、下载和 Markdown 渲染。
