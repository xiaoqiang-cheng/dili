# 终端与 PTY

## 两类终端

| 类型 | 文件 | 生命周期 |
| --- | --- | --- |
| 会话原生终端 | `server/terminal.ts` | 跟随联系人，停止会话时回收，重连恢复快照 |
| 底部 Shell | `server/shell-terminals.ts` | 独立于联系人，最多 16 个标签，关闭标签结束进程 |

两者都基于 node-pty，但不要互相复用状态：停止会话不能杀掉用户的 Shell，反之亦然。

## 生命周期

- 启动、停止都是单飞：`starting`/`stopping` 集合阻止并发。
- 停止会等待进程树回收；期间拒绝输入和重复启动。回收失败仍保留停止屏障，避免“假停止”。
- 服务关闭时等待自己启动的原生进程和终端树退出，再释放数据目录锁。
- 不是 Dili 启动的进程不在回收范围；不要尝试按端口或命令行猜杀。

## 重连与回放

- `server/terminal-replay.ts` 序列化最近 1000 行和光标状态；WebSocket 重连先重放再继续。
- 回放是内存快照，不写磁盘；服务重启后由原生历史负责。
- 输出积压超过 2 MiB 的连接会被断开，重连重建，防止内存无界增长。

## 输入

- 终端输入按原字节发送；多行粘贴分帧，避免一次 write 过大。
- 图片以路径方式暂存后粘贴（`server/attachments.ts`），是否接受取决于原生 TUI 和模型。
- 手机提供 Esc/Tab/方向键/Ctrl+C/回车的快捷按键；不要拦截原生 CLI 自己的快捷键。
- 输入法组合期间不要提交（`isComposing`）；终端内 Esc 属于原生 CLI，全屏切换用组合键。
- 页面隐藏时终端连接保持，但不要在前台不可见时持续做非必要轮询。

## 常见坑

1. 终端尺寸必须在挂载和容器尺寸变化时都发送 `resize`，否则换行错乱。
2. 重连后的首次输入不能早于回放完成，否则会插入到错误位置。
3. 大量输出时不要逐字符广播；合并到帧或直接写 socket，但保留背压判断。
4. 演示模式没有真实 PTY，不要伪造终端历史。
